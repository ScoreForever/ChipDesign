# TinyCNN-8 首轮训练结果

日期：2026-10-08。配置与冻结决策见
[MODEL_TRAINING_PLAN.md](MODEL_TRAINING_PLAN.md)。本页只记录实测结果，不把尚未通过的
目标写成已完成事项。

## 1. 训练运行

- 数据：Google Speech Commands v2；train 18,660、validation 2,100、test 2,430；
- 网络：TinyCNN-8，734 个可训练参数；
- 训练：30 epochs，batch 256，Adam，初始 lr `1e-3`，cosine decay，seed 0；
- 最佳 checkpoint：epoch 11，按 validation macro-F1 选择；
- 文件：`software/train/runs/tinycnn8/best.pt`（训练产物，被 gitignore）。

## 2. FP32 结果

| 指标 | Validation | Test |
| --- | ---: | ---: |
| Accuracy | 70.90% | 68.27% |
| Macro-F1 | 68.95% | 66.66% |

Test 每类召回率：

| yes | no | up | down | silence | unknown |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 86.67% | 57.53% | 78.52% | 69.14% | 95.56% | 22.22% |

Test 混淆矩阵（行是真实类别，列是预测类别，顺序同上）：

```text
[[351,  20,  15,   4,   4,  11],
 [ 24, 233,  12, 112,   1,  23],
 [  5,  31, 318,  24,   5,  22],

 [  0,   0,   0,   0, 387,  18],

```

主要问题是 unknown 召回率低，以及 no/down 互相混淆。本轮没有达到 85% 的阶段性
准确率目标，因此软件模型训练尚不能标记为最终完成。

## 3. PTQ 整数结果

- 校准：无增强训练集固定抽样 2048 条；
- 部署包：`data/tinycnn8.npz`（本地生成，被 gitignore）；
- 整数黄金模型 test accuracy：66.95%；
- 整数黄金模型 test macro-F1：65.40%；
- 相对 FP32 分别下降 1.32 和 1.26 个百分点，满足预定的 2 个百分点 PTQ 门槛。

结论：当前主要精度瓶颈是 FP32 模型容量、前处理和训练分布，而不是 INT8 PTQ；暂不
启用 QAT。

## 4. BN 对照实验

用无增强训练集重新累计 BN 运行统计后，validation macro-F1 从 68.95% 变为 69.00%，
但 test macro-F1 从 66.66% 降为 65.98%。收益没有跨集合复现，因此不采用
`best_bn.pt`，正式候选仍为原始 `best.pt`。

## 5. 下一轮需要确认的选择

在不修改 RTL 形状和六分类接口的前提下，优先建议做训练侧消融：降低加噪概率/强度，
比较无增强、轻增强和当前强增强三组；之后再评估 unknown 采样比例与损失权重。若这些
仍无法接近目标，才讨论修改 50 ms 无重叠前处理或增加网络通道数，因为后二者会扩大
软硬件联动范围。

## 6. 四分类对照实验

按确认后的控制变量方案，仅移除 silence/unknown，其他条件保持一致：同一
`20×16` log-mel、TinyCNN-8 主干、强增强、Adam、30 epochs、batch 256、seed 0。

- 类别：yes/no/up/down；模型参数量 716；
- 数据：train 12,440、validation 1,400、test 1,620；
- 最佳 checkpoint：epoch 27；
- FP32 validation accuracy / macro-F1：76.86% / 76.82%；
- FP32 test accuracy / macro-F1：77.16% / 77.09%；
- 无增强 train accuracy / macro-F1：76.68% / 76.65%。

FP32 test 每类召回率：

| yes | no | up | down |
| ---: | ---: | ---: | ---: |
| 84.69% | 72.35% | 82.47% | 69.14% |

FP32 test 混淆矩阵：

```text
[[343, 32, 25,  5],
 [ 37,293, 18, 57],
 [ 16, 17,334, 38],
 [ 17, 67, 41,280]]
```

四分类 INT8 PTQ 使用 2048 条无增强训练样本校准，test accuracy / macro-F1 为
76.36% / 76.36%，相对 FP32 accuracy 只下降 0.80 个百分点。部署包为
`data/tinycnn8_4class.npz`（本地生成，被 gitignore）。

结论：四分类消除了 silence 域偏移和 unknown 宽泛标签问题，较当前六分类 FP32 test
accuracy 提高 8.89 个百分点，但仍未达到 85%。无增强 train 与 validation/test 都在
约 77%，没有明显泛化间隙，说明当前更像输入表示/模型容量造成的欠拟合，而不是继续
增加 epoch 可以解决的问题。拒绝阈值尚未设计或评估。

## 7. 四分类无增强上限实验

为分离强增强与模型容量的影响，关闭时间平移、随机音量和背景加噪，其他模型与数据
配置不变，并把训练延长到 50 epochs。最佳 checkpoint 位于 epoch 48。

| 指标 | 无增强 Train | Validation | Test |
| --- | ---: | ---: | ---: |
| Accuracy | 82.07% | 83.71% | 82.47% |
| Macro-F1 | 81.98% | 83.68% | 82.38% |

FP32 test 每类召回率：

| yes | no | up | down |
| ---: | ---: | ---: | ---: |
| 90.12% | 80.74% | 88.40% | 70.62% |

FP32 test 混淆矩阵：

```text
[[365, 20, 15,  5],
 [ 17,327, 14, 47],
 [  9, 11,358, 27],
 [ 10, 71, 38,286]]
```

INT8 PTQ test accuracy / macro-F1 为 81.73% / 81.60%，相对 FP32 accuracy 下降
0.74 个百分点。部署包为 `data/tinycnn8_4class_noaug.npz`。

结论：去掉增强带来约 5.3 个百分点的测试准确率提升，说明原强增强确实超过了当前
模型的承载能力；但最终无增强 train 也只有 82.07%，且 38–50 轮已经平台化，训练、
验证、测试三者无明显间隙。因此在当前前处理和 716 参数结构下存在真实欠拟合，继续
单纯增加 epoch 很难达到 85%。最明显的剩余问题仍是 down 被识别为 no/up。

## 8. 四分类去 GAP / Flatten 分类头实验

保留两层 8 通道卷积，把 Pool2 的 `5×4×8` 按 NHWC 顺序展平为 160 维，直接连接
`FC(160→4)`。参数量从 716 增至 1,324；输入、数据划分、优化器、batch 256、seed 0
保持不变，两种增强均训练 50 epochs。

| 增强 | 最佳 epoch | Validation Acc. / Macro-F1 | Test Acc. / Macro-F1 |
| --- | ---: | ---: | ---: |
| 强增强 | 41 | 90.50% / 90.55% | **89.69% / 89.77%** |
| 弱增强 | 44 | 90.93% / 90.95% | **90.43% / 90.46%** |

增强定义：

- 强增强：±100 ms、音量 0.8–1.2、80% 加噪、SNR 10–30 dB；
- 弱增强：±50 ms、音量 0.9–1.1、40% 加噪、SNR 15–30 dB。

强增强 test 每类召回率：

| yes | no | up | down |
| ---: | ---: | ---: | ---: |
| 95.56% | 86.42% | 91.60% | 85.19% |

弱增强 test 每类召回率：

| yes | no | up | down |
| ---: | ---: | ---: | ---: |
| 95.56% | 88.15% | 93.83% | 84.20% |

结论：两组均超过原阶段目标（强增强 80%、弱增强 85%），且比对应 GAP 模型显著
提高。仅保留 Pool2 的时频位置、增加 608 个 FC 参数，就消除了此前约 80% 的平台，
说明 GAP 信息丢失是主要瓶颈，不需要先扩大卷积通道。

### 8.1 强增强 Flatten PTQ 与 RTL 部署验证

强增强最佳 checkpoint 已按当前 TFLite/gemmlowp 整数契约完成 PTQ。完整四分类
测试集（每类405条，共1620条）结果：

| 模型 | Test Accuracy | Macro-F1 |
| --- | ---: | ---: |
| 强增强 FP32 | 89.69% | 89.77% |
| 强增强 INT8 PTQ | **89.94%** | **90.00%** |
| 弱增强 FP32 | 90.43% | 90.46% |
| 弱增强 INT8 PTQ | **90.56%** | **90.58%** |

INT8 混淆矩阵（rows=true, cols=prediction）：

```text
[[390,  7,  1,  7],
 [  5,352,  1, 47],
 [  4, 10,371, 20],
 [ 10, 43,  8,344]]
```

逐类 recall：yes 96.30%、no 86.91%、up 91.60%、down 84.94%。PTQ 没有造成
精度退化，accuracy 相比 FP32 浮动 +0.25 个百分点，属于量化后决策边界的正常
小幅变化。

弱增强 INT8 逐类 recall 为 yes 96.30%、no 88.89%、up 93.58%、down 83.46%。

部署链已经同步切换为 Flatten：导出器生成 Conv1=0、Conv2=9、FC=81 的 256×64-bit
权重镜像；Python 黄金模型按 Pool2 NHWC 顺序展开160个输入；RTL 顶层移除 GAP，
直接执行 `FC(160→4)`。从测试集导出的100条真实语音已逐样本比较四个 raw INT32
logit，Python 整数模型与 RTL 全部 bit-exact 通过。

因此 TinyCNN-8-Flat 现已成为训练、量化、部署包、黄金模型和生产 RTL 的统一基线；
早期 GAP/六分类结果仅保留为实验历史。
