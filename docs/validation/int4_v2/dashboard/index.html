Fusion ablation, cycles / writes

Each fusion kind switched off in the compiler. Hatched cells no longer fit the 16 descriptors or 8 KiB SRAMs: fusion is what makes these models fit. In u4 models, ReLU is done by the requant clamp, so switching off ReLU fusion changes nothing.

What was decided

  • Adopted: single-rounding requant, unsigned u4 activations, a one-word parameter format, a shared setup multiplier, a vector element engine, narrow-kernel row padding, one depthwise weight row per tap, dual requant lanes, in-place Add and JTAG burst IRs.
  • Kept as a build option: TILE 8, since the die is not area-limited and the cycle cost is real.
  • Rejected: a third SRAM for a 16 KiB model store (only 8 KiB macros fit the die), one shared SRAM for model and activations, and a hardware switch for fusion (fusion changes the descriptor list, so the compiler owns it).
  • Not covered: multi-corner STA, IR and EM, a Vivado run and a board run; the full report is docs/INT4_V2_REPORT.md.
