# 无 CPU SoC 的 ASIC 面积审查

日期：2026-10-19。源码基线：`48958c0`，`exp/no_cpu`；EDA 证据分支：
`eda-results-2026-10-19`（`8e6df69`）。
本次审查不修改 RTL，不重跑 ASIC EDA，不把 FPGA LUT/DSP 数当成标准单元面积。
结果分支自带的 RTL 仍是另一套 SoC；本审查通过 `git show 48958c0:<path>` 核对
实际被测的无 CPU 源码，并以 reproduction/synthesis_filelist.f 核对综合入口。

## 1. 输入证据与限制

已核对以下实际工程证据：

- `POSTLAYOUT_METRICS_no_cpu.md`：源码版本、Genus 综合层级面积和正式后端结果。
- `eda_results/2026-10-19/formal/no_cpu/audit/report_area.rpt`：Innovus 层级及类别面积。
- 同目录 `geometry.csv`、时序与物理检查；reproduction 下的约束和源文件表。
- `backend_experiments/no_cpu_autosize_20261018/AUTOSIZE_DIAGNOSIS.md` 及对应
  `eda_results/2026-10-19/experiments/no_cpu_autosize/logs/` 的 1700/2100 µm 实验日志。
- `docs/ASIC_POSTLAYOUT_REPORT.md`：原主 SRAM 的宏型号、接口和物理尺寸。

工艺为 TSMC 180 nm，目标 50 MHz。正式结果是 **2800 µm core、3100.160 µm die**，
并非 2.4 mm die；其 DRC/antenna 为 0/0、JTAG SDF 后仿通过。
2100 µm core / 2400.160 µm die 是另一轮探索实验，布线完成、setup/hold
+0.861/+0.020 ns、DRC 0，但 antenna 5，未重跑 SDF，不能混用验收结论。

以下节省位数仍是 RTL 结构量，不是实测可消除 FF 数。结果分支没有公开完整映射网表、
库文件或数据库，因此还不能把 NPU 父层级进一步精确拆为各个 RAM 数组的门面积。

## 2. 先校正 die/core/单元面积的预算

实际每侧边距约 150 µm。1700 µm core 实验得到 2000.320 µm die，pad ring
检查通过且无 pad 越界。这证明约 2 mm 的目标首先受到 **核心密度/布线拥塞** 限制，
而非 IO 数量；若约束严格不超过 2000 µm，还需按 row/site 网格把尺寸略向下调整。

1700 µm core 的原始日志：

- `autosize_1700_place.log:1255`：初始 core utilization 81.491524%。
- `:1276`：标准单元面积 2.355548 mm² / 可分配行面积 2.885784 mm²，
  两者直接相除约 81.62%；与上一项的统计口径略有差异。
- `:2438`：优化时可分配面积降为 2.771330 mm²，density 约 84.8%。
- `:3073`、`:3102` 等：明确报 `exceeding max density`，无法继续修复大量网络。
- 存在明显早期布线溢出，实验在 CTS 前停止。

因此不能仅把 floorplan 压到 2 mm，或者只看 2.36 < 4 mm² 就认为放得下。
按初始可分配行面积作同口径的粗预算：

| 初始利用率目标（示例） | 映射单元预算 mm² | 相对 2.355548 mm² 需减少 |
|---:|---:|---:|
| 70% | 2.0200 | 14.2% |
| 65% | 1.8758 | 20.4% |
| 60% | 1.7315 | 26.5% |

这些不是闭合保证；固定单元、阻塞、CTS、修复和宏 halo 还会改变预算。
建议把第一轮 **无宏方案的综合面积目标设为 1.8–1.9 mm²（约减少 19–24%）**，
再在约 1700 µm core 上验证；若加入 SRAM，应重算宏占地、halo 和可放置行面积，
不能把宏方案的“标准单元降幅”直接套入上表。

总 report_area 为 2.686591 mm²，包含顶层单元，不能直接当成可放置 core 的面积。
其与综合值差约 14%，原报告特别标注了 `.lib vs LEF area` 口径差异，
不能全算成时钟树或后端额外插入面积。填充后 density=100% 也不代表逻辑拥塞。

## 2.1 实际面积把优化优先级指向哪里

综合层级是最适合直接比较的同口径数据：

| 模块 | 综合面积 mm² | 总综合面积占比 |
|---|---:|---:|
| NPU | 2.241124 | 95.14% |
| 命令控制器 | 0.096255 | 4.09% |
| JTAG transport | 0.018152 | 0.77% |

即便把控制器/JTAG 完全删除，理论上也只少约 4.86%，且失去所需功能。
不应继续以裁剪主机接口、异常恢复或可观测性作为达到目标的主线。

正式后端报告进一步给出：

- 全芯片 flop 类面积 **1.559172 mm²，约总 report_area 的 58.0%**，latch 为 0。
- NPU 的 flop 类面积 **1.483240 mm²**，占全芯片该类别约 95.1%。
- `array` 整块面积 **0.215942 mm²**；`requant` 整块 **0.066506 mm²**。
- NPU 除这两块子模块以外的汇总剩余约 **2.044300 mm²**，包括存储、
  读写选择/译码、累加池化、控制和门控，不能全归为 RAM。
- 扣除 array/requant 后，NPU 的其余 flop 类仍有约 **1.382651 mm²**。

这组数据支持“先查 FF 存储和访问网络”。直接把 array 砍半，若仅按 array 自身面积
估算，节省约 0.108 mm²，只占总报告约 4%；其外围变化另计。
即便极端地删除整个 requant，也仅约 0.067 mm²。因此二者都不应优先于存储改造。

统计注意：report_area 的 Clock Gate 列与 Flop 列存在重叠（RC_CG_MOD 子项可直接
核对），不能把 0.057205 mm² clock gate 再加到各主类别之和里；层级面积也不能
把父层与子层重复相加。当前没有各数组单独映射后的面积，不能给出未经验证的 RAM
精确占比或把 RTL 位数机械换算为库面积。

## 3. 当前活动设计

`my_soc_top -> npu_jtag_transport + npu_control_subsystem`，后者包含
`npu_command_controller + tinycnn8_npu_fused`。生产源列表只有七个 RTL 文件。
CPU、AXI、旧 DMA、主 SRAM、Debug Module 和旧参考 NPU 都不进入该设计。
删除这些保留源码不会进一步减少门面积。扩展端口默认关闭，综合可消除未使用分支。

NPU 主存储的声明量：

| 对象 | 声明 | 数据位 |
|---|---|---:|
| weight_mem | 256×64 bit | 16,384 |
| 激活 bank | 8×128×8 bit | 8,192 |
| psum_buf | 16×8×32 bit | 4,096 |
| win_buf | 4×8×32 bit | 1,024 |
| 合计 | 3,712 B | 29,696 |

另有模型参数 1,376 bit、PE 权重双 bank 512 bit、阵列数据/标记流水线、
量化器流水线，以及控制器的 staging、结果快照和计数器。

“SRAM 宏为 0”且 latch 类为 0，结合数组结构及大量 flop/组合面积，
可确认当前并未把这些存储实现为 SRAM 宏；应进一步提取 FF RAM、读选择树及写使能
的精确映射清单。
不能把没有 SRAM 宏当作最终优化目标：需要比较宏本体、halo、外围电路后的总物理面积。

## 4. 优先级最高：存储实现和物理读口

### 4.1 权重和激活映射到 SRAM 宏

权重存储应优先尝试：计算期间只读，空闲时装载/查询，端口需求最容易整理。
需要已验证的 SRAM wrapper、匹配的时序模型、Liberty、LEF 和相应物理实现支持。
现有综合脚本读取 RTL 和标准单元库，不包含针对 NPU 存储的宏实例化/映射适配。
仅增加 ram_style 属性不能保证 ASIC 存储映射。

将异步读改为匹配宏的同步访问时，需要同步调整权重 loader、地址预取、返回 valid
和调试查询的等待状态。若可用宏只有 32-bit 口，当前每行 64-bit 权重可能需要并行
两 bank，或两次读取后组装；后者会改变装载吞吐，必须测量是否还能隐藏在计算中。
即使可用宏容量大于 2 KiB，也应以其真实 LEF 面积加 halo 与标准单元 RAM 比较。

现成候选并非完全未知：原主存使用 **RA1SHD_2048x32M8，8 KiB、单端口、
byte 写使能、同步访问**，尺寸 554.595×723.85 µm，宏本体约 **0.4015 mm²**。
它可以作为第一轮真实对照，但有以下两条不同实验路线：

1. **先只替换权重**：保留激活 bank，降低改造范围。容量利用率虽只有 25%，
   仍可能比 2 KiB FF RAM 更省；64-bit 权重行需分两次 32-bit 读回组装，
   调整 loader 预取与 bank_ready，比较面积和推理周期。
2. **权重＋激活共用宏**：总数据 3 KiB 容量装得下，但现有权重预取、激活读取、
   requant 写回可能同时请求。必须仲裁、分时或增加小缓存与背压；容量足够
   不等于带宽满足。需要更低延迟时，应争取小容量/合适宽度的多个宏。

这里是把物理 SRAM 直接交给 NPU 控制，并不需要恢复 CPU、AXI 交叉开关或原 DMA。
也不能简单重新挂上主 SRAM 而保留 NPU 内部同份 FF 数组，否则会增加面积。
若未来增加模型容量，宏的独立封装和读返回 valid/ready 接口还可成为扩展存储的基础。

激活目前每拍读取四个连续 byte，同时可能写回一个 byte。不能不加分析地把它
塞进一个单端口 RAM。可选做法：

- 用适当的 1R1W 或分 bank 宏维持访问能力；核对同地址读写语义。
- 按生命周期拆成输入/Pool2 与 Pool1 两区。C1 读前者写后者，C2 反过来，
  FC 只读前者；利用阶段互斥减少每个物理块的同时读写需求。
- C2/FC 的四字节读取本来是对齐的，C1 的三个横向字节可能跨 word，需额外处理。

四个 byte bank 理论上足以支持任意起点的连续四字节读取，但每个 bank 的深度会变化，
是否更省取决于 SRAM 宏颗粒或标准单元 mux 实现，不能只比较 bank 数。

### 4.2 合并权重的计算读口与调试读口

`tinycnn8_npu_fused.sv` 中存在两个独立的权重读地址：

- 正常计算：`weight_mem[load_addr]`。
- 空闲调试：`weight_mem[debug_read_addr[10:3]]`，返回低/高 32 bit。

两者在协议上互斥，但 RTL 写成独立读表达式，可能形成额外的读选择逻辑，
或妨碍单读口宏匹配。应先在地址端选择计算/调试地址，再从唯一的物理读口取 64 bit，
最后选择返回半字。这个改动可保留所有现有空闲查询功能。

激活调试已通过 act_read_base 共用计算读地址，不应误判成同样的重复读口。
实际节省需要网表统计，不能仅凭表达式数量承诺减半读 mux。

### 4.3 没有合适 SRAM 宏时

仍可优先整理端口、译码和写使能，比较 FF RAM 与工艺允许的 latch-based RAM。
Latch RAM 需要被课程流程允许，并完成门控、透明窗、测试及 STA 约束验证；
不能直接把 always_ff 改成 latch 就交付。ROM 化或把训练权重固化到组合逻辑会
破坏当前模型更新能力，不应作为默认优化。

## 5. 保持当前整数结果的位宽优化

### 5.1 PE 局部和从 32 bit 收到 18 bit

每次阵列输出只包含四个 signed INT8 乘积：

`4 × [-16256,16384] = [-65024,65536]`。

18-bit signed 足够。可把 fused_ws_array 的内部 MAC/psum 传播和输出 deskew
改为 18 bit，在跨 K 累加前符号扩展回 INT32。最终 bias、池化和 logits 仍按 INT32。

按当前声明量，32 个 PE psum 寄存器加 28 个 deskew 寄存器，最多减少
`(32+28)×(32-18)=840 bit`。实际综合可能已优化掉部分符号扩展，所以这不是
840 个实际 FF 的保证值。历史临时 FPGA 实验已有非零向量验证，但不能替代本次 ASIC 映射。

### 5.2 psum_buf 可以考虑“窄的无偏累加＋末组加 bias”

不能直接把当前 psum_buf 改成 24 bit：当前第一组就加入任意 INT32 bias。
可改为先只累加输入乘积，在最后一组形成最终值时，再以 INT32 加 bias，之后再池化。

当前最大 K 为 FC 的 160；纯乘积和范围为 `[-2600960,2621440]`，23-bit signed 足够。
若 psum_buf 改为 23 bit，tile16 下可减少 `16×8×9=1152 bit` 的声明存储。
按 modulo 2^32 加法的结合律，最后加 bias 可保留原本逐组 INT32 wrap 的最终结果。

必须在 signed INT32 MaxPool **之前**完成 bias 加回；不能在任意 INT32 bias/wrap
契约下把它移动到 MaxPool 后面。实现可能增加末组加法路径或需要再流水，故要检查
净面积及 +1.05 ns setup 余量。验证需加入 INT32_MIN/MAX bias 与溢出翻转边界。
未来增加 K 时，位宽必须按最大归约长度重新推导。

### 5.3 内部 payload 的复位

PE act/psum、skew/deskew、部分量化数据流水线目前都有数据复位。
可研究仅复位 valid、状态、所有权与可观测输出，取消无效 payload 的复位，
减轻带复位单元、数据 mux 和 reset 分发成本。

前提是加载/valid 完整覆盖所有后续使用，不会在复位恢复后消费旧权重或未知数据。
尤其 PE 权重 bank 必须在 bank_ready 之前完成所有行装载；不能删除状态复位、
CDC 复位、结果快照清零或有明确查询语义的输出复位。

## 6. 用一定延迟换面积

### 6.1 真正实现 tile8/tile4

当前 `SPATIAL_TILE` 形参未使用，实际是 `localparam TILE_POS=16`。
tile 大小还写入 layer_tiles、窗口编号、tag、地址公式和 drain 条件，不能只改形参。

| tile | psum（保持32bit时） | 最大四/二/一个窗口存储 | 两者合计 |
|---:|---:|---:|---:|
| 16 | 512 B | 128 B | 640 B |
| 8 | 256 B | 64 B | 320 B |
| 4 | 128 B | 32 B | 160 B |

tile4 理论减少 480 B=3840 bit 的缓冲声明量，但权重重装更频繁，也可能暴露
PE 双 bank 生命周期等待。需把存储减少和额外 loader/control 一起综合，测周期数。
若与 23-bit psum 组合，节省不能简单相加，因为两者作用于相同存储。

### 6.2 4×8 阵列改为 4×4

核心已有 4×4 回归路径，可以两次输出通道 tile 覆盖原本八通道，维持相同网络和整数结果。
乘法 PE 从32降至16，输出累加、比较、部分流水线也会缩小，计算周期增加。

但生产控制器、64-bit/8-lane 模型装载及参数提交接口目前固定八 lane，不能只改一个参数。
需要重新适配四 lane 装载、权重地址组织和参数 tile 提交，并保持主机模型导出的语义。
总存储字节数也不会自然减半，因为仍保存同一网络的全部权重和激活。
现有后端 array 面积仅约 0.216 mm²，已说明砍 PE 的直接收益有限；
外围缓冲是否同步缩小仍需测量。应在存储/缓冲优化后再考虑这个折中。

### 6.3 量化器的精确时间复用

requant_lane 有一个全流水 32×32 乘法器、可变移位、舍入和饱和逻辑，
在 ASIC 中也是标准单元逻辑，不是免费 DSP。可比较分周期部分积乘法或移位器资源复用，
保持完整 Q31 舍入结果，但必须接受吞吐/延迟代价并调整 valid/tag 和窗口缓冲。

不能因为全网络平均量化操作较少就假设增加 II 不影响性能：Conv1 要产生 640 个
量化输出，目前阶段1000周期；II=2 时，仅服务这些输出就至少需要1280周期。
还要检查局部突发造成的窗口积压，防止节省乘法逻辑后又增加大量缓冲。

直接截短 Q31 multiplier、把所有含 bias 的累加器缩到24bit、或改 INT4，
都不属于当前任意参数契约下的无损优化，需另做量化/精度与 ABI 评估。

## 7. 较低优先级或需要专用 profile 的方向

- 当前四分类 FC 的高四 lane 不参与输出：若允许四分类专用构建，权重可压为
  Conv 648 B + FC 640 B =1288 B，相比声明的2048 B少760 B。
  但当前接口支持1–8类且权重可更新，不能在通用构建中静默删除这些lane。
- 权重深度256改241最多省120 B，激活1024改960最多省64 B；宏映射时可能完全不改变物理容量。
- 32-bit 地址中间量、除3/取模、动态 part-select 可通过窄的有符号坐标和显式计数器/LUT
  比较优化，但综合可能已经传播常量/缩宽，不能以 RTL 的 integer 声明直接推断电路很大。
  padding 的 -1 坐标必须保留，不能随意改为 unsigned。
- perf 计数器可设置可配置宽度；峰值等计数器高位可能早已被综合消除。
  32-bit 可编程 watchdog/任务号的缩宽会改变契约，需要显式范围检查或 ABI 说明。
- 控制器 bias/multiplier/shift staging 共560bit，结果快照256bit。应先报告其实际面积，
  不要为了小幅节省删除模型更新、结果所有权或用户要求的只读查询。
- JTAG CDC 同步器和复位保障不应作为主要削减对象。

## 8. 建议的实际实验顺序与验收

现有报告已确认 NPU、flop 和 array/requant/controller 的占比。
下一步需在同一工艺、同一50MHz约束下补齐 weight/activation/psum/window 的映射统计，
包括各数组实际 FF 数、读 mux、译码/写使能和门控面积。

1. **端口合并**：保留查询，权重计算/调试共用物理读口，单独 A/B 综合。
2. **宏适配**：优先权重，再激活；比较宏本体+halo+外围及布线后的总面积。
3. **无损收窄**：18-bit 阵列内部和，23-bit无偏psum/末组bias，payload复位优化，逐项比较。
4. **缓冲折中**：tile8/tile4，记录缓冲、控制、周期数和时序的完整变化。
5. **仍超标时**：4×4阵列或精确多周期requant；四分类压缩仅作明确的专用配置。

每项记录：综合标准单元面积、宏面积、映射后单元类别、物理插入开销、core利用率、
目标2mm die的布局布线状态、setup/hold WNS、DRC/antenna、核心周期和SDF后仿结果。
进行当前无 CPU 回归和原非零 golden 回归；位宽重排增加溢出和极值测试。
不能把各项独立节省量简单相加，也不能用 FPGA 节省百分比替代 ASIC 结果。

最有希望的大幅优化是 **SRAM/标准单元 RAM 实现与读口整理**；
如果工艺或课程流程不能提供适当存储宏，再把 **tile 缓冲缩减与计算时间复用** 提升为主线。
