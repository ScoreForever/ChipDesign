# INT4 重构后的面积优化分析（2026-10-31）

分析基于已提交的 `fb99fbe`，默认4×8、模型/激活各8KiB SRAM。
本轮按用户要求不完成 EDA。这里的位数是 RTL 声明与数据流的结构核算，周期来自功能仿真，
几何表是现有脚本的假设算术；都不能换算成已验证的 mm² 或收敛后的布局布线结果。
[计算记录](validation/npu_int4_area_options_20261031.json)保存来源指纹、公式项和周期数据。

## 本次 INT4 已消除什么

只计 psum tile、MAC双权重bank、激活链/行错位、PE局部和及输出对齐，INT8→INT4减少1912位声明存储：

| 数据结构 | 减少位数 |
|---|---:|
| 16位置×8列 psum，26→18bit | 1024 |
| 两个权重bank，8→4bit | 256 |
| PE激活链，8→4bit | 128 |
| 激活行错位，8→4bit | 24 |
| PE局部和，18→10bit | 256 |
| 输出列对齐，18→10bit | 224 |

还缩小了量化乘法/乘积寄存器、系数缓存、gather和权重暂存，删除了8列权重的两次读取拼接。
同时新增或扩大了 nibble 写掩码、部分byte检测和RMW控制，所以1912位不是全SoC净FF变化。
RAM推断、常量传播、使能/复位结构、mux和布线开销都要在映射后核实。

有三处不能继续直接截位：单个乘积最大64，需要signed8；四行局部和最大256，需要signed10；
K=1024累积最大65536，需要signed18。最大K极值已纳入回归。
bias及原始张量仍允许任意INT32值并有wrap语义，不能仅因操作数为INT4就把结果槽改成18bit。

两颗现有宏的几何尺寸仍为554.595×723.85μm，面积合计约0.8029mm²（历史库视图尺寸）。
打包减少占用并扩大可执行网络范围，**不减少现有宏实例的面积**，也不意味着整芯片面积减半。

## 近期优先项：控制与元数据

建议先探索以下不改变数值能力的改动，分别保留当前实现作比较，重新核对完整回归。

1. **在描述符读取时检查保留字及格式，不缓存全部16字。** 当前 d[11..14] 只用于检查0，d[15]只用于检查格式。
   可以用一个累积非法标志替代160位存储，理论减少159位及相关写选择逻辑。仍在 BASIC 阶段报错18，保持错误优先级、
   无激活写入、模型事务与trace事件语义。进一步压缩只用于合法性检查的高位时，也须先检查再丢弃。
2. **数据寄存器减少复位。** 权重、psum、量化payload等若由valid/已装载标志严格保护，部分数据可不复位，
   只清控制状态。收益是复位mux、复位扇出和布线，不是减少存储位数。必须证明复位后每个有效输出只依赖已初始化数据，
   包括abort、watchdog、部分权重bank装载及连续任务；不能直接批量删除reset分支。
3. **按已验证边界缩小运行期索引。** 默认激活地址为14bit nibble偏移，模型地址13bit byte偏移；目前较多运行期寄存器为16bit。
   应区分有效地址、完整容量端点、带padding的虚拟负地址及跨度：例如16384这个跨度需要15bit，不能一律截成14bit。
   验证阶段仍保留足够的乘积/范围宽度，防止溢出后通过检查。非负Q15系数缓存可明确存15bit并在乘法入口补0，收益较小。

这些是候选方案，尚未写入RTL，也未给出面积收益承诺。相比新增跨层行缓存或第二套计算单元，更符合当前面积优先目标。

## 可直接选择的4×4配置

4×4已通过与4×8相同的五算子、融合/独立、容量、尾lane和背压功能检查；模型须按列数重新打包。
无需减少算子集、引入CPU或改变INT4数值精度。ASIC `EDA_NPU_COLS=4`、独立物理流程 `--cols 4`、FPGA构建 `--cols 4` 选择它。

相对4×8，4×4减少16个MAC；对psum、四个结果槽、双权重bank、PE链/局部和、列对齐、通道缓存及tag流水的选定项核算，
减少2548位声明存储。其中1152位来自psum，512位来自结果槽。它不等于2548个最终触发器，也未包含全部控制变化。

下表是当前课程结构用例的冷启动执行周期，不包含JTAG上传、模型验证和输出读取；KWS为显式PTQ导入的模型，未测分类精度。

| 网络用例 | 4×8 | 4×4 | 周期增加 |
|---|---:|---:|---:|
| MNIST | 5696 | 5781 | 1.5% |
| KWS | 3234 | 5866 | 81.4% |
| HAR | 823 | 1202 | 46.1% |

三者周期比的几何均值约1.391，即增加39.1%。它只代表这三个用例，不能推广为任意网络性能损失。
MNIST网络通道较窄，8列利用有限，所以列数减半的代价较小；KWS存在充分利用8列的层，代价明显。
仍建议默认4×8，保留4×4作为面积紧张且可接受延迟时的完整功能构建配置，待EDA同事提供同约束面积和时序后再定默认值。

## 较大收益但会影响吞吐的选项

| 选项 | 结构上的可能收益 | 主要代价 |
|---|---|---|
| 空间tile从16降为8 | 8列psum再少1152位及选择逻辑 | 相同大张量的权重tile装载次数可能接近翻倍；当前RTL固定16，需单独改调度并验证 |
| 结果槽4→2 | 8列payload少512位，另有位置/标志存储 | 在途预留、Pool窗口、ret_slot映射和信用必须联动；可能频繁阻塞 |
| 减小读缓存或写队列 | 减少缓存tag/data、队列和转发mux | SRAM单端口争用、RMW、量化写回背压会增加，不能只改数组深度 |
| 较小的物理SRAM宏 | 可能直接缩小宏和halo | 需要真实4KiB等宏视图；会降低容量上限，尤其INT32中间张量不享受INT4减半 |

结果槽压力不是假设：专用压力用例达到4槽并有430周期等待；普通融合CNN和KWS也达到4槽峰值，只是当前没有slot等待。
高压存储测试达到8项队列峰值并有显著写背压。因此不建议未经模型集合评估就把两个队列和结果槽同时缩小。

不能把8KiB宏的RTL地址范围改小，就记作4KiB宏面积；库中必须存在更小且物理交接完整的宏。
将两颗宏合成一颗还会改变总容量、读写并行性和仲裁。它是下一种产品容量/带宽配置，不能作为保持本版能力的等价替换。
限制量化只支持2的幂以删除乘法器也会失去一般Q15系数，故不作为本次默认优化。

## SRAM 摆放会形成面积下限

当前几何脚本的 `west_stack` 将两个宏竖直叠放。按现有宏高、26μm halo、20μm通道和150μm PAD边距计算，
即使逻辑明显缩小，所需core边长仍至少1620μm，对应die约1920μm。距离1950μm上限只剩30μm。
这意味着“继续删逻辑”未必能继续减小die，反而适合把省下的空间用于降低单元密度、保留hold修复和布线余量。

横向 `south_row` 因宏宽小于高，几何下限较低。下表只把**假设标准单元面积**输入现有公式，
名义利用率0.60；没有跑综合、合法化、电源规划或布线，不能当作INT4面积预测或最终候选。

| 假设标准单元面积 | west_stack die边长 | south_row die边长 |
|---|---:|---:|
| 0.80mm² | 1920μm | 1780μm |
| 1.00mm² | 1920μm | 1880μm |
| 1.20mm² | 1980μm | 1980μm |

脚本还预留了6μm网格取整余量，实际候选需满足完整检查。旧INT8版本的south_row曾发生setup失败，
不能依据这个几何表认定新摆放可用；EDA同事应在INT4上重新比较时序、宏周边通道和拥塞。
历史78.7%是扣除SRAM halo/电源环后的单元密度，不是布线利用率；全局overflow、详细DRC与hold须独立检查。

## 跨Conv流式连接的适用性

已有软件行缓存探索已同步INT4：在8行、宽8/16/32、通道2→4→3的两个Conv例子中，
完整中间张量为128/256/512B，三行缓存峰值48/96/192B；软件顺序计算与逐层参考一致。
但两颗SRAM宏若仍保留，省下的只是占用，额外行缓存和调度反而增加逻辑。
窄图宽8的权重装载量还从448B增至896B，宽16/32的例子不增加。这不是RTL周期估计。
它适合未来容量或带宽瓶颈优化，当前不优先为缩面积而引入。

建议下一轮先做描述符缓存/复位与索引精简的独立实验；在1950μm外形内保留可布线空间，
同时让EDA同事比较4列/8列和横向/纵向宏摆放。是否牺牲容量、采用更小SRAM，等实际模型需求与宏视图确定后再决定。
